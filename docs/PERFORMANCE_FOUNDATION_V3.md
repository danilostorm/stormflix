# Performance Foundation v3

This release completes StormFlix Packages 1 and 2 without replacing the proven Playback Engine.

## Runtime priority

`internal/workload` provides one gate per SQLite pool. Fresh video or game playback heartbeats pause catalog-heavy workers; stale sessions never strand jobs. SQL errors fail open to avoid deadlocking maintenance. Admin reports active waiters, pause counts and accumulated pause time by worker category.

All FFmpeg playback work remains globally bounded. Responsive artwork conversion also acquires the shared process scheduler and is bypassed while playback is active.

## Home Query v2

The cold grouped Home no longer calls `catalogEntities` for the whole catalog. SQLite selects only visible row membership using bounded window queries, uses an indexed rebuildable genre projection instead of parsing and sorting every `genres_json`, caps every rail at 24 cards, caps library rails at 12 and genre rails at 8, then resolves all distinct cards in one `IN` batch. Dynamic profile rails remain parallel and outside the static snapshot.

The automated 50,000-title test fails if a cold synthetic Home exceeds 1.5 seconds or a cache hit exceeds 500 milliseconds on the CI runner. Browser first-content p95 is measured in production because network, device rendering and artwork cache state cannot be proven by a server-only unit test.

## Browser delivery

- hls.js 1.7.1 and the exact hevc.js runtime used by Playback Engine v6 are embedded, checksum-tested and lazily loaded.
- Music and Games JavaScript/CSS are generated by `node scripts/build-web-bundles.mjs` into content-addressed files. CI runs the same command with `--check`.
- Hashed bundles and pinned vendor assets use immutable one-year cache headers; HTML and the screen manifest use `no-cache`.
- Local artwork URLs advertise responsive `srcset` widths. The authenticated asset handler negotiates AVIF or WebP, caches by source size/mtime/width/format and falls back to the original without breaking Home.

## Measurements

Admin `/api/v1/admin/server` now includes:

- `home_performance`: server p50/p95/p99, cache states and client first-content/response/render p95;
- `sql_performance`: bounded timings and errors for each Home SQL group;
- `background_work`: current playback priority and per-worker pause counters;
- `ffmpeg_resources`: global active/video/waiter limits;
- SQLite pool, WAL, schema and migration-ledger state.

Active playback diagnostics include `plan_ms`, `first_frame_ms`, `startup_ms`, `stall_count` and `last_stall_ms`.

## Scope boundary

Performance Foundation v3 itself did not promote `libmedia`. Playback Engine v7
subsequently added it as a guarded original-file route without replacing any
mature fallback; see `PLAYBACK_ENGINE_V7.md`. Long-duration memory, seek, HDR,
audio/subtitle and real-device observations remain the acceptance boundary.
